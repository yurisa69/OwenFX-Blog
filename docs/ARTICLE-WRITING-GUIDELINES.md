# OwenFX 文章写作规范

本文档规定 OwenFX 文章 Markdown 源文件的标题层级、编号格式和三级标题展示方式。新文章和明确要求修改的文章必须遵循本规范。

## 1. 适用范围

- 适用于仓库 `content/articles/` 中的文章 Markdown 源文件。
- Markdown 源文件应直接写入规定的标题层级和编号，不依赖网页端自动转换编号。
- 管理后台不提供独立的编号修正按钮。点击「修正并发布」时，会先自动修正可识别的 H1/H2/H3 标题编号，再重新检查并发布；不改标题层级和正文。仍有无法安全判断的问题时会停止发布，并提示人工调整。
- 新文章从创建时遵循本规范；历史文章仅在用户明确要求修改时按本规范调整，不进行未经授权的批量改写。
- 本规范规定文章内容结构和三级标题的展示要求；不代表本次文档更新已经修改网站渲染组件或 CSS。

## 2. 规范生效时间与历史版本

- 原文章编号校验规则首次生效时间为 **2026-11-14 19:04:41 UTC**；本次 H1/H2/H3 层级修订自 **2026-11-16** 起执行（对应 UTC 时间 **2026-11-15T19:03:22.089Z**）。
- 本次修订生效前已经发布的文章保持原样，不因历史标题层级和编号格式影响正常阅读；未修改的历史文章不进行强制改写。
- 生效后新建并发布的文章必须符合本规范；草稿可以暂不符合。
- 本次修订生效前发布的文章如重新发布，必须按当前规范校验；即使正文没有修改，也不豁免发布检查。
- 恢复历史版本时，仍按文章版本创建时间及当时有效的规范处理；之后再次主动编辑并发布时，须符合当前规范。
- 历史版本缺少创建时间或时间无法解析时，按需要校验处理，不自动豁免。

## 3. 标题层级与编号规则

### 3.1 一级标题

文章的一级标题使用一级 Markdown 标题（H1），编号使用中文数字加顿号。

格式：

```markdown
# 一、项目方案

# 二、环境准备

# 三、安装配置

# 四、验证维护
```

- 一级标题按文章内容顺序递增，使用“一、二、三、四……”。
- 编号与标题之间不额外插入空格。
- 不使用英文句点或中文句号代替顿号。
- 不属于执行步骤的结构性章节可以不编号，例如“前言”“引言”“概述”“目录”“总结”“结语”“参考资料”“参考文献”“延伸阅读”“附录”“致谢”和“相关链接”。这类标题不参与一级步骤编号计数。

### 3.2 二级标题

二级标题使用二级 Markdown 标题（H2），编号使用阿拉伯数字加英文半角句点。

格式：

```markdown
# 一、环境准备

## 1. 检查系统版本

## 2. 更新软件包

## 3. 安装必要依赖
```

- 每个一级标题下的二级标题从 `1.` 开始，按正文出现顺序递增。
- 不使用 `1.1`、`1.2` 等多级编号形式。

### 3.3 三级标题

三级标题使用三级 Markdown 标题（H3），编号直接使用 Unicode 带圈阿拉伯数字字符，例如 \`①\`、\`②\`、\`③\`，不添加圆形底色或其他徽标样式。

格式：

\`\`\`markdown
# 一、环境准备

## 1. 检查服务器

### ① 确认操作系统版本

### ② 检查磁盘空间

## 2. 准备配置文件

### ① 创建项目目录

### ② 配置环境变量
\`\`\`

编号要求：

- 每个二级标题下的三级标题从 \`①\` 开始，按正文出现顺序递增，依次使用 \`②\`、\`③\` 等字符。
- 使用 Unicode 带圈阿拉伯数字字符本身，不使用普通数字加 CSS 圆形底色、边框或徽标模拟。
- Markdown 源文件直接写入带圈字符，网页按原字符显示，不再通过前端渲染器转换或包裹数字。
- 常用编号范围为 \`①\` 至 \`⑳\`；超过 20 项时可继续使用 Unicode 带圈数字 \`㉑\` 至 \`㊿\`。

### 3.4 四级及以下内容

四级及以下内容优先使用无序列表表达，不继续叠加数字标题层级。

格式：

```markdown
# 一、部署前准备

## 1. 检查服务器环境

### ① 确认系统信息

- 确认操作系统版本。
- 确认磁盘空间和内存。
- 确认当前用户具有所需权限。

## 2. 准备配置文件

### ① 创建项目目录

- 准备环境变量。
  - 敏感变量只保存在服务端环境中。
  - 不要将真实密钥提交到仓库。
```

确有必要时可以使用无序列表的嵌套层级表达从属关系；不要为了形式整齐而创建过多层级。

## 4. 禁止使用的编号形式

- 一级标题不得使用 `##`；必须使用 H1 和中文数字顿号，例如 `# 一、环境准备`。
- 二级标题不得使用 `###` 或 `1.1`；必须使用 H2 和阿拉伯数字英文句点，例如 `## 1. 安装 Docker`。
- 三级标题不得使用 `####`、`1.1.1` 或普通阿拉伯数字加句点；必须使用 H3 和 Unicode 带圈阿拉伯数字，例如 `### ① 检查运行状态`。
- 不使用 `1-1` 等形式继续叠加编号层级。
- 同一层级中不得混用不同编号体系或标点。

正确示例：

```markdown
# 一、项目与部署方案

## 1. 确定部署架构

### ① 选择服务组件

### ② 规划服务端口

## 2. 确定部署方式

### ① 准备运行环境

# 二、环境准备

## 1. 检查系统版本

### ① 查看系统信息

### ② 检查可用资源
```

## 5. 与 Markdown 内容的配合

- 一级标题使用 H1（`#`）；二级标题使用 H2（`##`）；三级标题使用 H3（`###`）。
- 代码块、表格、引用、图片和链接按内容需要正常使用，不要把编号写进代码块来代替标题。
- 命令执行顺序、配置项和注意事项可使用有序列表；如果属于标题层级，仍必须遵循第 3 节的规则。
- 标题编号直接写入 Markdown 源文件。不得依赖 CSS、前端脚本或渲染器在展示时自动生成或改写编号。
- H3 编号直接使用 Unicode 带圈阿拉伯数字字符，网页不得再添加圆形底色、边框或徽标。
- 不为满足编号规则而拆分原本连贯的内容；优先保证文章结构清晰、步骤可执行。

## 6. 发布前检查

发布新文章或提交明确要求修改的文章前，检查以下事项：

- [ ] 一级标题使用 H1，中文数字加顿号，例如 `# 一、环境准备`。
- [ ] 二级标题使用 H2，阿拉伯数字加英文句点，例如 `## 1. 安装 Docker`。
- [ ] 三级标题使用 H3，直接使用 Unicode 带圈阿拉伯数字字符，例如 `①`、`②`。
- [ ] 每个一级标题下的二级标题从 `1.` 开始编号。
- [ ] 每个二级标题下的三级标题从 `①` 开始编号，并连续递增。
- [ ] 四级及以下内容优先使用无序列表。
- [ ] 没有使用 `1.1`、`1.1.1` 等多级数字编号替代标题层级。

- [ ] Markdown 源文件中的层级和编号与网站显示一致。
- [ ] 未擅自批量修改其他历史文章。
