# OwenFX 文章写作规范

本文档规定 OwenFX 文章 Markdown 源文件的标题层级与编号方式。新文章和明确要求修改的文章必须遵循本规范。

## 1. 适用范围

- 适用于仓库 `content/articles/` 中的文章 Markdown 源文件。
- Markdown 源文件应直接使用规定的编号格式，网站渲染端不负责将阿拉伯数字自动转换为中文数字。
- 新文章从创建时遵循本规范；历史文章仅在用户明确要求修改时按本规范调整，不进行未经授权的批量改写。
- 本规范只约束文章内容结构，不要求修改网站页面、Markdown 解析器或现有文章业务数据。

## 2. 标题层级与编号规则

### 2.1 一级大步骤

文章正文中的一级大步骤使用中文数字加英文句点，通常使用二级 Markdown 标题（`##`）。

格式：

```markdown
## 一. 项目与部署方案
## 二. 环境准备
## 三. 安装与配置
## 四. 验证与维护
```

编号按文章内容顺序递增，使用“一、二、三、四……”；标题编号中的分隔符统一使用英文半角句点 `.`，不使用顿号或中文句号。

### 2.2 二级小步骤

某个一级大步骤下的具体小步骤使用阿拉伯数字加英文句点，通常使用三级 Markdown 标题（`###`）。

格式：

```markdown
## 一. 环境准备

### 1. 检查系统版本

### 2. 更新软件包

### 3. 安装必要依赖
```

每个一级大步骤下的小步骤从 `1.` 重新编号，按正文出现顺序递增。

### 2.3 三级及以下内容

三级及以下的补充说明优先使用无序列表，不继续叠加数字编号层级。

格式：

```markdown
## 一. 部署前准备

### 1. 检查服务器环境

- 确认操作系统版本。
- 确认磁盘空间和内存。
- 确认当前用户具有所需权限。

### 2. 准备配置文件

- 创建项目目录。
- 准备环境变量。
  - 敏感变量只保存在服务端环境中。
  - 不要将真实密钥提交到仓库。
```

确有必要时可以使用无序列表的嵌套层级表达从属关系；不要为了形式整齐而创建过多层级。

## 3. 禁止使用的编号形式

文章的大步骤和小步骤不要混用以下形式：

- 一级大步骤使用 `## 1. 项目与部署方案`。
- 二级小步骤使用 `### 1.1 检查系统版本`。
- 用 `1.1.1`、`1-1` 等形式继续叠加编号层级。
- 同一层级中混用中文数字、阿拉伯数字、中文顿号和不同句点。

正确示例：

```markdown
## 一. 项目与部署方案

### 1. 确定部署架构

### 2. 规划服务端口

## 二. 环境准备

### 1. 检查系统版本

### 2. 更新软件包
```

## 4. 与 Markdown 内容的配合

- 文章标题使用一级标题（`#`）；正文的大步骤使用二级标题（`##`）；对应的小步骤使用三级标题（`###`）。
- 代码块、表格、引用、图片和链接按内容需要正常使用，不要把编号写进代码块来代替标题。
- 命令执行顺序、配置项和注意事项可使用有序列表；如果属于正文中的大步骤或小步骤标题，仍必须遵循第 2 节的编号规则。
- 标题编号直接写入 Markdown 源文件。不得依赖 CSS、前端脚本或渲染器在展示时改写编号。
- 不为满足编号规则而拆分原本连贯的内容；优先保证文章结构清晰、步骤可执行。

## 5. 发布前检查

发布新文章或提交明确要求修改的文章前，检查以下事项：

- [ ] 一级大步骤使用中文数字加英文句点，例如 `## 一. 环境准备`。
- [ ] 二级小步骤使用阿拉伯数字加英文句点，例如 `### 1. 安装 Docker`。
- [ ] 每个一级大步骤下的小步骤从 `1.` 开始编号。
- [ ] 三级及以下内容优先使用无序列表。
- [ ] 没有使用 `1.1`、`1.1.1` 等多级数字编号替代标题层级。
- [ ] Markdown 源文件中的格式与网站预期显示一致。
- [ ] 未擅自批量修改其他历史文章。
