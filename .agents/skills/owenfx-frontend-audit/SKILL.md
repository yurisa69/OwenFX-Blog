# OwenFX 前端审查规范

## 1. 默认只读

本 Skill 的默认任务是审查，不修改源码、不提交、不推送、不部署。只有用户明确要求修复或实施时，才可进入修改流程；开始修改前先列出目标文件和范围。

不得把审查建议当成用户已经批准的修改。

## 2. 审查前建立项目上下文

按以下顺序建立事实基准：

1. 检查当前分支、最新 Commit、工作区状态及目标页面/组件的实际源码和调用链。
2. 阅读仓库根目录 `AGENTS.md` 与 `docs/DEVELOPMENT_GUIDELINES.md`。
3. 阅读与审查范围对应的专项规范和 Skill。
4. 检查当前测试、依赖和实际运行结果。
5. 最后将 README 作为项目概览和辅助导航；若与源码、正式规范或测试不一致，不得以 README 覆盖实际证据。

OwenFX 当前基础可从源码定位：
- 页面与组件通常位于 `app/`、`components/`；业务辅助逻辑通常位于 `lib/`。
- Supabase SSR 客户端封装可从 `lib/supabase/` 定位。
- 文章内容、软件数据和媒体存储路径以当前仓库实现及正式规范为准。

目录和实现可能演进。以上是定位线索，不是跳过源码检查的理由；不要臆测文件路径、组件行为或接口契约。

## 3. 审查范围

根据用户指定范围逐项检查，至少覆盖适用项：

### 页面与视觉
- 页面结构、间距、字体、颜色、主题变量、玻璃效果和层级是否一致。
- 动画、粒子、光效、颜色过渡、背景运动和玻璃效果是否保留既有质量与已确认参数；不得通过减少动效、降低强度或静态化背景换取性能分数。
- 性能问题是否先通过实际测量定位，再从渲染、状态更新、重复计算、DOM、媒体加载、网络、缓存、代码拆分或 GPU 合成等实现层面处理。
- 深色/浅色主题切换是否闪烁、丢失状态或产生 hydration 问题。
- 卡片尺寸、标签换行、图标比例、图片加载和空状态是否稳定。
- 首页、文章页、软件库、软件详情、个人中心、管理后台之间的视觉一致性。

### 交互
- 搜索、登录、收藏、评论、赞赏、导航、筛选、分页和编辑器操作是否保持原有行为。
- 鼠标、键盘、触控、焦点、禁用和加载状态是否合理。
- 防止重复提交、误触、点击区域重叠和异步状态竞争。
- 检查移动端底部导航：首页、软件、分类、我的，确认入口、顺序和功能未被意外改变。

### 文章系统
- Markdown 与富文本双向转换是否保留标题、列表、引用、表格、图片、链接和代码块。
- 代码语言标识、高亮、复制、预览和安全过滤是否一致。
- 草稿、发布、修订历史、恢复、GitHub 内容同步和失败重试是否有明确状态。
- 文章标题编号遵循 `docs/ARTICLE-WRITING-GUIDELINES.md`。

### 软件库与详情
- 首页精选推荐是否仍为软件图标卡片。
- 软件卡片标签规则与详情页标签规则是否分离。
- 详情页软件信息引用块、官方下载、网盘资源和赞赏入口是否正确。
- 软件详情和文章详情是否保持独立。
- 不托管软件安装包；检查外链安全、失效反馈与数据状态。

### 动效与性能保真
- 对比修改前后的动画时长、数量、强度、颜色变化频率、运动范围和触发条件，确认未被擅自削弱。
- 检查性能优化是否针对已定位瓶颈，是否避免以删除动画、减少粒子、降低光效、关闭玻璃效果或静态化背景作为替代方案。
- `prefers-reduced-motion` 仅在用户主动选择时作为无障碍辅助功能处理；仓库实现状态必须通过源码核查，未发现时标注「待实现/待验证」。

### 安全与可访问性
- 不可信内容是否经过验证和安全渲染；外部链接是否正确设置安全属性。
- 客户端是否意外暴露服务端密钥或管理数据。
- 表单是否具备标签、错误提示、键盘操作和合理语义。
- 图片是否有替代文本，动态区域是否避免无意义的屏幕阅读器播报。

## 4. 问题分级

按影响分级并给出证据：
- **严重**：可导致数据泄露、权限绕过、数据损坏、主要功能不可用或生产事故。
- **高**：核心用户流程中断、明显安全风险、严重布局或交互故障。
- **中**：部分设备/页面功能异常、明显性能回归、可访问性缺陷。
- **低**：轻微视觉不一致、非关键体验问题或维护性建议。

每条问题必须说明：
1. 文件路径及组件/函数/代码位置（能确定时给出）。
2. 复现条件或触发路径。
3. 实际影响与风险。
4. 建议修复方向。
5. 是否需要数据/API/依赖变更。

没有证据时标注「待验证」，不要把推测写成事实。

## 5. 验证策略

- 先确定项目已有的脚本和测试，再选择适用命令。
- 只读审查可使用源码阅读、静态检查和测试；不得为了验证而修改生产数据或真实用户记录。
- 需要浏览器验证时，记录实际访问页面、视口尺寸、主题和交互路径。
- 不要声称已验证手机、平板、生产站点或某个功能，除非确实执行了对应检查。
- 区分「未发现问题」「未检查」和「无法验证」。

## 6. 审查报告格式

1. 审查范围与基准 Commit。
2. 总体结论。
3. 按严重程度排序的问题清单。
4. 关键文件与调用链。
5. 已执行的测试/检查及结果。
6. 未覆盖范围和限制。
7. 修复建议（不自动实施）。

审查结束后保持仓库不变：不创建文件、不改源码、不产生 Commit、不推送、不触发 Vercel 部署。


## 7. Vercel Toolbar 辅助验收

需要定位布局偏移、交互响应或无障碍问题时，按 `.agents/skills/owenfx-vercel-tooling/SKILL.md` 使用 Vercel Toolbar：

- Layout Shifts：检查字体、图片/视频尺寸、异步内容、卡片高度、标签换行和动画引起的布局偏移。
- Interaction Timing：检查搜索、导航、筛选、弹层、主题切换等关键交互的耗时。
- Accessibility Audit：检查语义、表单标签、焦点、键盘操作、颜色对比和控件名称；Toolbar 结果不等于完整 WCAG 合规认证。
- 重点覆盖玻璃效果、首页软件卡片、软件详情、文章详情及移动端布局；记录页面、视口、设备、主题、Commit 和复现步骤。
- 默认不创建 Preview Deployment。优先使用已获准的现有部署或本地环境；启用 Toolbar、安装依赖或修改项目设置前先取得用户明确授权。
- Toolbar 不可用时标注「未执行/无法验证」，不得以目测冒充 Toolbar 检查。
