# OwenFX 统一语言规范

## 1. 规范依据与适用范围

- 本 Skill 以仓库根目录 `docs/DEVELOPMENT_GUIDELINES.md` 为唯一直接依据：统一语言、提交说明、分支命名、Git 术语、操作流程和报告分别对应其第 1 至第 6 节；安全边界和规范优先级同时遵循第 7、8 节。
- 开始 OwenFX 项目协作或 Git 操作前，应先阅读当前版本的 `docs/DEVELOPMENT_GUIDELINES.md`；不得仅凭本 Skill 或历史记忆替代对正式规范的核对。
- 本 Skill 负责提炼和执行统一语言要求，不得修改、覆盖或扩展正式开发规范中的规则。
- 本 Skill 与正式开发规范不一致时，以 `docs/DEVELOPMENT_GUIDELINES.md` 为准，并应修正本 Skill。
- 适用于面向用户、开发者、项目协作者展示的文字，包括聊天说明、项目文档、Git 操作说明、提交记录、协作沟通、检查结果、发布与部署报告。

## 2. 默认语言

- 所有面向用户、开发者和项目协作者展示的说明，默认使用简体中文。
- Commit 提交说明必须使用简体中文，准确概括本次完整修改，不使用英文前缀作为主要说明。
- Pull Request（合并请求）的标题、正文、审查意见和合并说明使用简体中文。
- 版本发布说明、变更记录、回退说明、检查结果和部署报告使用简体中文。
- 不在同一条提交说明或操作报告中无必要地中英混排。
- 确有必要的技术名词可以保留英文原文，并在首次出现时用中文解释。

## 3. 分支名称

- 正式分支固定为 `main`，必须保留原名，不翻译、不重命名。
- 普通开发分支优先使用简体中文，名称应简短、明确。
- 分支名称不得包含空格、控制字符或无意义编号。
- Git 固定引用和平台要求的名称（例如 `main`、`origin`、`HEAD`）保留原样。
- 如果外部工具、脚本或部署集成不兼容中文分支名称，先说明具体限制，再选择兼容方案；不得静默改用英文名称。

## 4. Git 术语统一用语

在聊天、提交报告、项目文档和协作说明中统一使用以下中文表达：

| Git / 平台术语 | 统一中文用语 |
| --- | --- |
| Commit | 提交 / 提交记录 |
| Commit Message | 提交说明 |
| Push | 推送 |
| Pull | 拉取 |
| Fetch | 获取远程更新 |
| Branch | 分支 |
| Merge | 合并 |
| Pull Request | 合并请求 |
| Tag | 版本标签 |
| Checkout / Switch | 切换分支 |
| Revert | 反向撤销提交 |
| Reset | 重置 |
| Rollback | 回退 |
| Restore | 恢复 |
| Working Tree | 工作区 |
| Staging Area | 暂存区 |
| Remote Repository | 远程仓库 |
| Local Repository | 本地仓库 |
| Conflict | 合并冲突 |

- 在面向用户的说明中优先使用表格中的统一中文用语；首次出现时可附带英文原文帮助识别。
- 不得为了中文化而翻译或改写可执行命令、参数、固定分支名称、Commit SHA、文件名、目录名、API 字段或配置键。

## 5. 命令与技术标识

以下内容必须保留准确原文：

- Git 命令及参数，例如 `git commit`、`git push origin main`。
- 固定分支和远程名称，例如 `main`、`origin`、`HEAD`。
- Commit SHA、文件名、目录名、API 字段、环境变量名和配置键。
- 代码、终端输出、日志和平台返回的原始状态值。

中文化的是命令周围的解释文字，不是命令本身。不得为了语言统一修改实际可执行内容或技术标识。

## 6. GitHub 原生界面边界

- GitHub 网站自身的按钮、菜单、系统状态和产品界面语言由 GitHub 账户或产品界面设置决定。
- 仓库文件、Skill 或提交说明不能强制改变 GitHub 原生界面的显示语言。
- 描述 GitHub 界面时，使用简体中文解释；必要时在括号中保留界面上的英文原文，便于用户定位。

## 7. 执行与检查

每次涉及 Git 操作或协作文案时，检查：

1. 面向用户和协作者的说明是否使用简体中文。
2. Commit 提交说明是否为简体中文，并准确描述实际修改。
3. 分支名称是否遵循中文优先原则，固定名称是否保持原样。
4. Git 术语是否使用统一中文表达。
5. 命令、参数、SHA、路径、字段和配置键是否保持准确原文。
6. 发布、检查和部署报告是否使用简体中文，且状态描述有实际证据支持。
7. 是否错误声称能够通过仓库文件改变 GitHub 原生界面语言。

发现不符合项时，在提交或交付前修正。不得为了满足语言规范而改变 Git 操作本身、技术标识、仓库历史或用户已确认的项目决定。

## 8. 权威文件

- 统一语言规范：`docs/DEVELOPMENT_GUIDELINES.md` 第 1 节。
- 提交说明：第 2 节；分支命名：第 3 节；Git 术语：第 4 节。
- 提交与推送流程：第 5 节；检查与部署报告：第 6 节；安全与项目保护：第 7 节；规范优先级：第 8 节。
- 本 Skill 是执行指引，不是第二份独立规范。
- 正式规范发生变化时，应先核对正式文件，再同步更新本 Skill；不得反向以本 Skill 修改正式规范。
