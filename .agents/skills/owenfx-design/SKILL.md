# OwenFX 视觉与交互设计规范

## 1. 目标与优先级

本 Skill 用于保护并延续 OwenFX 已有的视觉语言和交互，不是重新设计网站的授权。默认采用渐进式修改：先识别现有页面、组件、CSS 变量和交互，再做满足当前需求的最小变更。

优先级从高到低：
1. 用户在当前任务中最新明确提出的要求。
2. 用户此前确认且仍有效的 OwenFX 产品规则。
3. 仓库当前实现、设计 token、组件和页面行为。
4. 本规范中的通用建议。

发现冲突时先说明，不自行推翻已确认决定。

## 2. 视觉基线

- 保持 OwenFX 当前深色/浅色主题体系、渐变背景、玻璃质感、柔和边框、光效与卡片层次。
- 延续现有字体、字号层级、间距、圆角、阴影、颜色变量和组件风格；优先复用 CSS variables 与已有组件。
- 不将局部设计偏好扩展为全站换肤，不擅自引入新的 UI 框架、图标库或动画依赖。
- 玻璃效果应保证文字对比度、边界可辨识和内容可读性；模糊、透明度和发光不能遮蔽信息。
- 图标优先使用项目已有图标资源和实现方式；不要用不一致的 Emoji 代替正式界面图标。

## 3. 页面与产品边界

- 首页「精选推荐」展示软件图标卡片，不得改造成网盘资源列表。
- 点击软件图标进入独立软件详情页。
- 文章页面与软件详情页是两类独立内容，不得合并成同一详情模板。
- 软件详情页应承载软件介绍、开发者、版本、平台、更新时间、官方官方下载入口、网盘资源链接和赞赏支持。
- 软件详情页的开发者、版本、平台、更新等信息左侧使用与文章同款引用块样式；该规则适用于所有软件详情页，不限于单个软件示例。
- 软件分类显示名称使用「Android」「Windows」等既定短名称，不额外添加「软件」二字，除非用户明确改变规则。
- 保留赞赏、登录、微信公众号入口及现有用户功能。

## 4. 软件库卡片与标签

必须区分「软件库卡片标签」和「软件详情页标签」，不可混用规则。

### 4.1 软件库卡片标签

- OBS Studio 的示例规则：将「直播」与「录屏」合并为一个「直播录屏」标签，再显示「开源免费」；这张卡片最多显示两个四字标签。
- 其他软件若使用两字标签，一张卡片最多显示三个两字标签。
- 标签显示数量、长度和合并方式以用户针对该软件或页面明确指定的规则为准；不要把 OBS 的两个四字标签规则错误推广为所有软件的统一规则。
- 不得为了卡片整齐而修改数据库标签、标签关联或筛选语义；展示层规则与底层数据应分开处理。

### 4.2 软件详情页标签

- 「免费开源」必须拆分为两个独立标签：「免费」和「开源」。
- 不得在详情页将二者合并显示成「免费开源」或「开源免费」。
- 修改标签展示前，先检查数据来源、标签映射函数、卡片渲染与详情页渲染，避免影响筛选功能。

## 5. 导航与响应式布局

- 移动端底部导航保留：首页、软件、分类、我的；不得擅自删除、改序或更换入口路由。
- 已确认的图标调整仅涉及「软件」和「分类」两个图标：分类使用原软件图标；软件使用应用商店/九宫格应用图标风格。不得交换入口、顺序或功能。
- 搜索、登录、主题切换等按钮保持既有尺寸、点击区域、状态反馈与相邻布局；不得让搜索占位压缩旁边按钮。
- 同时检查手机、平板和桌面端。避免横向溢出、底部安全区遮挡、触控目标过小、卡片跳动和误触。
- 不要只凭桌面截图判断移动端布局。

## 6. 动效与无障碍

- 保留现有动效节奏和用户已明确指定的时长、颜色、透明度及运动范围；未被要求的参数不得顺手调整。
- **性能优化不得以减少动态效果为代价。** 不得擅自删除、禁用、缩短动画，不得降低粒子数量、光效强度、颜色变化频率或运动效果，也不得静态化背景或关闭玻璃效果来掩盖性能问题；应优化渲染、计算、资源加载和动画实现方式，保持正常模式下的视觉表现。
- 不叠加多套竞争的 hover、focus、active 动画，不制造页面首次加载闪烁或主题切换白屏。
- 尊重用户主动启用的 `prefers-reduced-motion: reduce` 无障碍设置：仅在该模式下减少非必要位移、循环动画和视差，并保留必要状态反馈与内容可理解性。不得把它作为默认性能优化手段；是否已实现须核查源码，不能仅凭本规范认定已上线。
- 键盘可操作，焦点清晰；交互状态不只依靠颜色表达。
- 动效在低性能移动设备上应避免持续高成本重绘。

## 7. 修改前检查与交付

1. 检查目标页面、相关组件、样式文件、全局变量和调用链。
2. 搜索相同组件是否被多个页面复用，确认影响范围。
3. 记录现有行为和用户已确认的边界。
4. 只修改当前任务要求涉及的部分；不重排无关组件，不批量格式化。
5. 检查深浅主题、窄屏/宽屏、hover/focus/active/disabled 和减少动态效果模式。
6. 汇报具体文件、可见变化、验证范围和未验证项目。

禁止把设计审查结果直接当作修改授权；用户只要求审查时保持只读。
