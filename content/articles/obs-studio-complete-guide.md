# OBS Studio 完整教程：从入门录屏到高级直播与进阶玩法

OBS Studio 是一款免费、开源、跨平台的视频录制与直播软件。它不只是一个屏幕录制工具：通过场景、来源、音频混音器、滤镜、转场和输出配置，你可以把它搭建成游戏录制工具、软件教程工作台、网课直播间、产品演示系统，甚至是一套可以远程控制和自动化运行的内容制作环境。

这篇教程按学习难度分为三个部分：

- **入门**：安装 OBS、认识界面、添加画面和声音，完成第一段清晰、完整的录屏。
- **高级**：掌握画布与输出分辨率、编码器、录制格式、音频滤镜、多轨录制和直播参数。
- **进阶玩法**：搭建专业场景、回放缓存、虚拟摄像机、浏览器来源、投影、插件和自动化控制。

本文以 Windows 版 OBS Studio 为主要演示环境。macOS 和 Linux 的菜单名称、采集权限及部分来源类型可能不同；涉及平台差异的地方会单独说明。OBS 的界面会随版本更新略有变化，具体选项以你安装的版本为准。

# 一、入门：安装 OBS 并完成第一次录制

## 1. 下载、安装与首次启动

### ① 从官方渠道下载

OBS Studio 官方下载地址：

[OBS Studio 官方下载](https://obsproject.com/download)

根据操作系统选择 Windows、macOS 或 Linux 版本。不要从不明软件下载站获取安装包，也不要为了“解锁功能”安装来历不明的修改版。

截至本文编写时，OBS 官方发布页已列出 OBS Studio 33.0.1。版本更新可能改变界面、插件兼容性和部分功能，安装时以官方发布页显示的最新稳定版为准：

[OBS Studio 官方版本发布页](https://github.com/obsproject/obs-studio/releases)

### ② 安装时需要注意什么

Windows 用户下载官方安装程序后，按向导完成安装即可。普通用户通常不需要修改安装目录，也不需要额外安装所谓的录屏解码包。

macOS 用户首次使用屏幕采集、摄像头和麦克风时，需要在系统隐私与安全设置中授予对应权限。Linux 用户则要留意桌面环境、Wayland/X11、PipeWire 和发行版打包方式对采集来源的影响。

### ③ 第一次启动运行自动配置向导

首次启动 OBS 时，通常会出现自动配置向导。也可以从菜单中打开：**工具 → 自动配置向导**。

根据主要用途选择：

- **优先用于直播**：让向导根据网络上传能力和电脑性能估算直播设置。
- **优先用于录制**：让向导侧重本地录制质量。
- **只使用虚拟摄像机**：如果主要是把 OBS 画面输出给会议软件，可先完成基础配置，再单独设置虚拟摄像机。

向导给出的结果是起点，不是绝对最优值。完成后先录制一段短视频，确认画面、声音和性能，再决定是否手动调整。

## 2. 认识 OBS 主界面

### ① 场景：决定当前要呈现哪一套画面

场景可以理解为一个完整的画面方案。例如：

- 桌面教程：屏幕、摄像头、标题和提示框。
- 游戏录制：游戏画面、摄像头、麦克风和游戏声音。
- 休息画面：背景图、文字和音乐。
- 结束画面：结束提示、社交账号和背景动画。

一个场景可以包含多个来源。切换场景时，OBS 会按照场景中保存的布局切换画面。

### ② 来源：决定画面由什么组成

来源是场景里的具体内容。常见来源包括：

| 来源类型 | 作用 |
| --- | --- |
| 显示器采集 | 捕获整个显示器 |
| 窗口采集 | 捕获指定软件窗口 |
| 游戏采集 | 在 Windows 上采集游戏画面 |
| 视频采集设备 | 摄像头、采集卡等设备 |
| 图像 | 添加 PNG、JPG 等图片 |
| 媒体源 | 播放本地视频或音频 |
| 文本 | 添加标题、说明和提示 |
| 浏览器 | 显示网页、弹幕或网页叠加层 |
| 颜色源 | 添加纯色背景或色块 |

来源列表的上下顺序决定了画面的遮挡关系：列表中更靠上的来源通常显示在更靠前的位置。比如摄像头画面要叠加在游戏画面上，就把摄像头来源放在游戏来源上方。

### ③ 音频混音器：检查声音是否进入 OBS

音频混音器会显示桌面声音、麦克风以及其他音频来源的电平。说话时观察麦克风电平是否变化，播放电脑声音时观察对应的桌面或应用音频电平是否变化。

如果电平始终不动，先检查设备选择和系统权限，不要急着添加大量音频滤镜。

### ④ 预览区与控制区

预览区用于摆放、缩放和裁剪来源。控制区常见操作包括开始推流、开始录制、启动虚拟摄像机、工作室模式和设置。

录制前确认控制区显示的是你准备使用的操作，避免把“开始推流”误当成“开始录制”。

## 3. 创建第一个录屏场景

### ① 新建场景

在“场景”面板点击加号，创建一个场景，例如命名为“桌面教程”。名称尽量按用途命名，后续场景变多时更容易管理。

### ② 添加显示器采集

在“来源”面板点击加号，选择“显示器采集”，创建新来源并选择要录制的显示器。

如果电脑连接了多个显示器，务必确认选择的是正确屏幕。录制前检查是否会把私人聊天、通知、密码管理器或其他不适合公开的内容一起录进去。

### ③ 调整画面大小与位置

选中来源后，可以拖动边框调整大小和位置。右键来源还可以打开变换菜单，常用操作包括：

- 适应屏幕：让来源完整显示在画布中。
- 拉伸到屏幕：强制铺满画布，可能改变画面比例。
- 居中到屏幕：将来源放到画布中心。
- 重置变换：恢复来源原始变换状态。

尽量使用“适应屏幕”，不要为了铺满画布而随意拉伸，避免画面变形。

### ④ 使用窗口采集代替整个屏幕

如果只需要录制浏览器、编辑器或某个软件，优先考虑窗口采集。它能减少无关桌面内容进入视频的机会，也更适合制作软件演示教程。

不同 Windows 版本和显卡驱动可能提供不同的窗口捕获方式。如果画面黑屏或冻结，可以尝试切换采集方法、确认目标窗口没有被最小化，并检查 OBS 与目标程序是否运行在兼容的权限级别。

### ⑤ 使用游戏采集录制游戏

Windows 用户录制游戏时，可以优先尝试“游戏采集”。选择捕获特定窗口或自动捕获全屏游戏，并在游戏启动后检查预览画面。

如果游戏采集无法正常工作，再尝试窗口采集或显示器采集。某些游戏、反作弊系统和独占全屏模式可能限制捕获方式。

## 4. 配置麦克风和电脑声音

### ① 选择正确的音频设备

进入 **设置 → 音频**，检查桌面音频和麦克风/辅助音频设备是否选择了正确设备。

如果你使用 USB 麦克风、耳机麦克风或外置声卡，不要完全依赖“默认设备”。明确选择设备可以减少系统切换默认输出后 OBS 录不到声音的问题。

### ② 通过电平判断音量

对着麦克风正常说话，观察麦克风电平；播放电脑声音，观察桌面或应用声音电平。

录制教程时，通常希望人声清楚且稳定，背景声音不要盖过讲解。不要只看电平颜色判断音质，还要实际监听录制结果。

### ③ 避免重复采集导致回声

如果同时启用了全局桌面音频和应用音频采集，同一段声音可能进入 OBS 两次，形成音量叠加或回声。

使用应用音频采集时，检查是否还需要全局桌面音频。Windows 10 2004 及更新版本、Windows 11 的应用音频采集能力可按 OBS 官方指南配置；也可以在支持的窗口采集或游戏采集中启用音频捕获。

[应用音频采集官方指南](https://obsproject.com/kb/application-audio-capture-guide)

## 5. 设置基础录制参数并完成第一次录制

### ① 设置录制保存位置

进入 **设置 → 输出 → 录制**，先选择一个空间充足、容易找到的文件夹。不要把长时间录制文件放在容量很小的系统分区。

建议按项目建立文件夹，例如：

- Videos/OBS/Screen-Tutorials
- Videos/OBS/Game-Recording
- Videos/OBS/Live-Archive

### ② 选择录制格式

新手建议优先使用 MKV 作为录制容器。录制过程中如果 OBS 或电脑意外退出，MKV 通常比 MP4 更不容易因文件未正常结束写入而整体损坏。

录制结束后，如果剪辑软件或上传平台需要 MP4，可以使用 OBS 的 **文件 → 重新封装录制** 将 MKV 转换为 MP4 容器。重新封装不是重新编码，通常不会重新压缩视频画面。

### ③ 选择录制质量

如果刚开始使用 OBS，可以先用“简单”输出模式中的高质量预设。等你了解编码器、码率控制和音轨后，再切换到“高级”模式。

不要一开始就把所有参数调到最高。录制质量越高，文件通常越大，对编码器、磁盘和系统资源的要求也越高。

### ④ 录制并检查结果

点击“开始录制”，讲解或操作一两分钟，再点击“停止录制”。

检查以下内容：

- 画面是否完整，有没有黑屏、裁切或比例变形。
- 麦克风是否清楚，有没有爆音、断音或明显底噪。
- 电脑声音是否存在，是否和画面同步。
- 鼠标、窗口和文字是否足够清晰。
- 视频是否可以正常播放、拖动进度条和导入剪辑软件。

第一次录制通过后，再开始制作正式内容。

# 二、高级：画面、音频、编码与直播配置

## 1. 理解画布分辨率、输出分辨率和帧率

### ① 基础画布分辨率

基础画布分辨率（Base Canvas Resolution）决定 OBS 场景设计所使用的工作尺寸。可以把它理解为你摆放显示器、摄像头、文字和图片时使用的“画布”。

常见横屏视频可以从 1920×1080 开始；如果你的主要素材是 2560×1440，也可以使用 2560×1440 作为画布，但这会增加输出和编码负担。

### ② 输出分辨率

输出分辨率（Output Scaled Resolution）决定最终录制或推流的视频尺寸。

例如，画布为 2560×1440，输出为 1920×1080，OBS 会将画面缩放到 1080p 输出。这样可以保留较高分辨率的工作画布，同时控制最终视频尺寸。

改变基础画布分辨率后，可能需要重新调整来源的位置和尺寸；改变输出分辨率通常不会让原有场景布局发生同样的变化。

### ③ 帧率如何选择

| 使用场景 | 建议起点 |
| --- | --- |
| 软件教程、桌面讲解 | 30 FPS |
| 普通网课、产品介绍 | 30 FPS |
| 游戏录制、快速运动画面 | 60 FPS |
| 需要流畅展示快速操作 | 60 FPS，先测试性能 |

60 FPS 并不意味着画面一定更清晰，它主要增加运动画面的流畅度，同时提高编码和系统负载。静态桌面教程通常没有必要为了数字更大而强行使用 60 FPS。

## 2. 配置高级录制输出与编码器

### ① 从简单模式切换到高级模式

进入 **设置 → 输出**，将输出模式切换为“高级”。这样可以分别配置直播、录制、音频轨道和编码器。

建议先只调整录制部分，确认稳定后再设置直播，避免一次修改太多参数，出了问题不知道是哪项导致的。

### ② 选择硬件编码器还是软件编码器

常见编码器类型：

- **NVIDIA NVENC**：使用 NVIDIA 显卡的专用编码单元，适合有 NVIDIA 显卡的电脑。
- **AMD AMF**：使用 AMD 显卡的硬件编码能力。
- **Intel Quick Sync**：使用支持该功能的 Intel 图形硬件。
- **x264**：使用 CPU 进行软件编码，兼容性较广，但可能占用较多 CPU 资源。

如果电脑有可用的硬件编码器，可以优先测试硬件编码。硬件编码不等于完全不占用资源，游戏本身、显卡渲染和编码仍然会共同竞争系统资源。

### ③ 录制质量参数怎么选

在高级录制设置中，不同编码器会显示不同的码率控制选项，例如 CQP、CRF、ICQ 或质量预设。它们不是完全相同的参数，不能把某一种编码器的数值直接套用到另一种编码器。

可以按以下原则调整：

- 质量优先：选择质量导向的码率控制方式，逐步测试画面细节和文件大小。
- 文件体积优先：适当降低质量等级或使用更高压缩效率的编码设置。
- 性能优先：选择更快的编码预设，必要时降低输出分辨率或帧率。
- 录制游戏：先确认游戏帧率稳定，再调整编码质量，不要让 OBS 编码挤占游戏所需资源。

如果使用 NVIDIA NVENC，CQP 可以从 18–23 左右作为测试区间；数值越低通常意味着质量更高、文件更大。该区间只是起点，实际效果取决于内容、显卡、编码器版本和个人对文件大小的要求。

### ④ 关键帧间隔与配置预设

直播平台通常会对关键帧间隔、编码格式、码率和分辨率提出要求。应优先遵循直播平台当前的官方推流规范，而不是直接照搬其他平台或几年前的参数。

本地录制与直播的目标不同：录制可以更重视画质和后期空间；直播则必须同时考虑上传带宽、平台限制和观众端播放稳定性。

## 3. 录制多音轨，给后期剪辑留空间

### ① 为什么要分离音轨

如果麦克风、游戏声音、聊天软件和背景音乐全部混在同一条音轨里，后期很难单独调整某个声音。

多音轨录制可以让你在剪辑软件中分别控制人声、游戏声音和其他音源。例如人声太小，可以只提高麦克风音轨，而不必把游戏声音也一起放大。

### ② 启用需要的音轨

在 **设置 → 输出 → 录制** 中启用多条音轨，然后打开音频混音器的高级音频属性，为每个来源勾选对应音轨。

一个实用的分配示例：

| 音轨 | 内容 | 用途 |
| --- | --- | --- |
| Track 1 | 麦克风 + 游戏/桌面声音 | 完整混音，方便快速预览 |
| Track 2 | 麦克风 | 单独处理人声 |
| Track 3 | 游戏或应用声音 | 单独控制软件/游戏音量 |
| Track 4 | 聊天软件 | 后期调整通话声音 |
| Track 5 | 背景音乐 | 后期替换、静音或调整音乐 |

这只是示例。你可以根据自己的制作流程调整，不需要为了凑数量启用所有音轨。

### ③ 检查容器和剪辑软件兼容性

多音轨录制建议优先选择支持多音轨的容器，例如 MKV。不同播放器可能只播放其中一条音轨，不能仅凭播放器听到的声音判断其他音轨是否录制成功。

导入剪辑软件后，确认每条音轨都存在，并试听麦克风、桌面音频和其他来源。

## 4. 优化麦克风：降噪、压缩与限幅

### ① 降噪滤镜

在麦克风来源上右键，选择“滤镜”，可以添加降噪类滤镜。降噪适合处理风扇声、空调声等相对稳定的背景噪声。

降噪强度并不是越高越好。设置过强可能让人声出现水下感、断字或金属音。先录制短样本，再根据实际声音调整。

### ② 噪声门或扩展器

噪声门可以在声音低于阈值时降低或关闭麦克风输入，减少停顿时的环境噪声。扩展器则可以更平滑地降低较小的声音。

如果你在键盘敲击声较多的环境中录制，先调整麦克风位置和输入增益，再考虑噪声门。阈值过高会切掉轻声说话的开头和结尾。

### ③ 压缩器

压缩器可以缩小声音过大和过小之间的差距，让人声听起来更稳定。压缩器通常需要调整阈值、比例、启动时间、释放时间和补偿增益。

不要直接套用所谓“主播万能参数”。不同麦克风、说话距离和音量差异很大，建议边说话边监听，并避免压缩后出现明显的呼吸声放大或底噪抬升。

### ④ 限幅器

限幅器用于限制音量峰值，降低突然大声说话导致爆音的风险。它不能修复已经失真的录音，也不能替代正确的麦克风增益设置。

### ⑤ 一个实用的处理顺序

可以从以下顺序开始测试：

1. 降噪：先处理持续背景噪声。
2. 噪声门或扩展器：控制停顿时的环境声。
3. 压缩器：平衡人声动态。
4. 限幅器：限制过高峰值。

滤镜顺序和参数需要根据实际音源调整。完成后一定要录制样本检查，不要只凭预览电平判断。

## 5. 调整直播输出与网络稳定性

### ① 先确认直播平台的推流规范

在 **设置 → 直播** 中选择平台服务，或者按平台要求配置自定义服务器地址和推流密钥。

推流密钥属于账号敏感信息，不要截图公开、写入文章、提交到 GitHub，也不要发送给他人。怀疑泄露时应立即在平台后台重置。

### ② 码率要结合上传带宽

直播码率不是越高越好。应根据平台限制、视频分辨率、帧率和网络稳定性确定。

不要把测速软件显示的瞬时上传峰值当作可持续推流能力。最好在网络较忙的时段进行测试，并为其他设备和网络波动留出余量。

### ③ 关键帧间隔和音频码率

按平台官方要求设置关键帧间隔、视频编码和音频码率。平台规范发生变化时，应以平台最新说明为准。

### ④ 区分三种常见卡顿

- **网络掉帧**：通常与上传带宽、路由、Wi-Fi 干扰或推流服务器连接有关。
- **渲染延迟**：OBS 来不及完成场景合成，可能与 GPU 负载、复杂来源或高分辨率有关。
- **编码延迟**：编码器处理速度跟不上输出速度，可能与编码预设、CPU/GPU 资源竞争有关。

出现卡顿时，先打开 **查看 → 统计信息**，观察网络丢帧、渲染延迟和编码延迟分别是多少，再针对对应原因调整。不要把所有卡顿都归结为网络问题。

## 6. 场景、来源与画面布局的进阶管理

### ① 使用分组管理来源

来源较多时，可以创建分组，例如“摄像头组件”“标题组件”“背景组件”。这样移动、隐藏或调整一组元素会更方便。

### ② 使用来源锁定避免误触

布局完成后，可以锁定背景、边框和固定装饰来源，防止录制过程中误拖动。需要调整时再临时解锁。

### ③ 使用裁剪而不是拉伸

按住 Alt 拖动来源边缘可以裁剪画面。裁剪适合去掉窗口边框、无关区域或摄像头画面边缘。

裁剪与缩放是不同操作：裁剪减少可见区域，缩放改变显示尺寸。不要通过拉伸来掩盖比例不匹配的问题。

### ④ 使用滤镜和混合模式

视频来源可以添加色彩校正、锐化、色度键等滤镜；图片和文字来源也可以通过透明度和混合方式融入场景。

滤镜会增加处理负担。复杂场景出现性能问题时，先禁用不必要的滤镜和浏览器来源，观察是否改善。

# 三、进阶玩法：打造专业录制与直播工作流

## 1. 用多场景搭建完整内容制作流程

### ① 设计一套常用场景

可以建立以下场景作为模板：

- **开场**：标题、频道标识、背景音乐。
- **桌面教程**：软件窗口或显示器、摄像头、人声。
- **重点讲解**：放大某个窗口区域，添加步骤提示。
- **全屏演示**：只显示需要展示的软件或游戏。
- **休息**：休息提示、倒计时和背景画面。
- **结束**：结束语、关注提示和后续内容入口。

场景名称应简洁且有规律，后续通过快捷键切换时不容易选错。

### ② 复用场景和来源

如果多个场景需要同一个摄像头或标题组件，可以考虑复用已有来源，而不是每个场景都重新创建一套设备来源。

复用可以减少重复配置，但修改共享来源时也会影响引用它的场景。调整前先确认影响范围。

### ③ 使用场景转场

OBS 支持淡入淡出、滑动等转场效果。可以为不同场景设置合适的转场时长，让画面切换更自然。

不要给所有场景都使用过长转场。软件教程需要清晰、迅速地切换操作画面；直播节目则可以根据内容节奏选择更柔和的转场。

## 2. 使用工作室模式控制直播画面

### ① 预览与节目输出的区别

工作室模式会将画面分为预览和节目输出。你可以先在预览区调整来源、切换场景，再通过转场按钮将新画面发送到节目输出。

这对直播很有用：可以提前准备下一场景，而不会让观众看到你拖动来源、调整文字或移动摄像头的过程。

### ② 什么时候适合开启

- 直播中需要频繁切换场景。
- 需要在切换前检查文字、画面和来源是否正确。
- 需要调整布局但不希望修改过程直接出现在节目画面中。

如果只是录制简单桌面教程，工作室模式不是必需功能。

## 3. 回放缓存：保存刚刚发生的精彩片段

### ① 回放缓存的工作方式

回放缓存会在内存中持续保留最近一段时间的画面。你设置好缓存时长并启动回放缓存后，按下保存快捷键，就可以把刚刚发生的内容保存成视频文件。

它适合游戏精彩瞬间、临时演示结果和直播中的突发片段。

### ② 设置缓存时长

进入 **设置 → 输出**，在高级输出模式下找到回放缓存相关选项，设置缓存时长并启用功能。

缓存时间越长，通常需要占用越多内存。不要在内存不足的设备上盲目设置很长的缓存。

### ③ 设置保存快捷键

进入 **设置 → 快捷键**，为“启动回放缓存”“停止回放缓存”和“保存回放”分配快捷键。

建议选择不容易与游戏或常用软件冲突的组合键，并在正式使用前测试保存路径和文件是否正常。

## 4. 虚拟摄像机：把 OBS 画面接入会议软件

### ① 虚拟摄像机能做什么

虚拟摄像机可以把 OBS 输出画面作为摄像头提供给 Zoom、Teams、Discord 等支持摄像头输入的应用。

你可以先在 OBS 中组合摄像头、屏幕、文字和背景，再在会议软件中选择 OBS Virtual Camera。

### ② 启动与选择输出内容

点击控制区的“启动虚拟摄像机”，然后打开会议软件的摄像头设备列表，选择 OBS Virtual Camera。

根据当前版本的虚拟摄像机设置，可以选择输出节目画面、预览画面、指定场景或指定来源。需要对外展示时，通常应选择节目输出，避免把尚未准备好的预览画面发给会议参与者。

### ③ 检查分辨率和画面比例

会议软件可能会再次缩放 OBS 输出。提前检查画面比例、文字大小和摄像头位置，避免共享后文字过小或画面被裁切。

[虚拟摄像机官方指南](https://obsproject.com/kb/virtual-camera-guide)

## 5. 浏览器来源、弹幕和动态叠加层

### ① 添加浏览器来源

浏览器来源可以在 OBS 场景中加载网页内容，常见用途包括直播提醒、聊天框、动态标题、网页仪表盘和自定义叠加层。

添加时填写可信网页地址，设置宽度和高度，并检查网页是否允许在 OBS 内正常加载。

### ② 使用本地网页制作自定义画面

如果你会 HTML、CSS 和 JavaScript，可以制作本地网页作为浏览器来源，例如：

- 动态显示视频标题和章节。
- 展示直播倒计时。
- 制作简单的消息提示和进度条。
- 使用 CSS 动画制作转场或信息卡片。

本地网页可以在 OBS 的浏览器来源中加载，但要注意资源路径、字体、网络请求和浏览器缓存。不要加载来源不明的网页脚本，也不要把敏感 Token 写在公开页面中。

### ③ 控制浏览器来源的性能

浏览器来源本质上需要渲染网页。动画过多、视频背景、复杂脚本和多个网页实例都可能增加 CPU/GPU 负担。

如果 OBS 出现渲染延迟，先逐个关闭浏览器来源进行对比，不要只通过降低输出码率来解决网页渲染问题。

## 6. 投影功能：把预览或节目画面显示到其他屏幕

### ① 预览投影和节目投影

OBS 可以把预览画面或节目输出投影到窗口或指定显示器。投影适合现场演示、活动导播、教室投屏和多屏监看。

### ② 常见使用方式

在预览区或节目画面上点击右键，找到投影相关选项，选择窗口投影或目标显示器。

如果电脑连接了采集卡、外接显示器或现场大屏，先确认显示器排列和分辨率，再进行投影，避免把 OBS 控制界面误投到观众屏幕。

## 7. 插件、脚本与自动化控制

### ① 插件能扩展什么能力

OBS 插件可以扩展转场、滤镜、设备支持和工作流能力。安装插件前先确认：

- 插件是否来自可信作者或官方项目页面。
- 是否支持当前 OBS 版本和操作系统。
- 是否有明确的安装说明、更新记录和卸载方式。
- 是否需要额外运行服务或访问网络。

不要把来历不明的 DLL、脚本或压缩包直接放进 OBS 目录。

### ② OBS 33 及之后版本的插件兼容性

OBS Studio 33.0 对插件加载机制进行了调整。官方说明第三方插件有新的安装位置，旧位置会在过渡期继续兼容，但未来版本可能进一步收紧。

因此，升级 OBS 前先检查关键插件是否支持新版本，并备份配置。不要在主力直播环境中未经测试就批量升级所有插件。

### ③ 使用脚本自动化重复操作

OBS 支持 Lua 和 Python 脚本能力，可用于自动切换场景、更新文本、控制来源显示状态等。脚本适合处理重复性任务，但应先理解脚本权限、依赖和运行环境。

不要直接运行来源不明的脚本。需要使用 Python 脚本时，还要确认 OBS 当前构建所支持的 Python 运行环境和依赖。

### ④ 使用 WebSocket 进行远程控制

OBS WebSocket 可以让外部程序与 OBS 通信，实现远程切换场景、控制录制、读取状态等自动化操作。

如果启用 WebSocket：

- 设置独立且足够强的连接密码。
- 不要把服务端口直接暴露到公网。
- 只允许可信的本机或内网设备连接。
- 需要远程访问时优先使用安全的 VPN 或受控网络。
- 不要把连接密码写进公开仓库或前端网页。

远程控制能力越强，越需要限制访问范围。

## 8. 配置备份、迁移与长期维护

### ① 备份配置文件

OBS 的配置通常包含场景集合、配置文件、快捷键和其他用户设置。重要项目完成后，建议通过 OBS 的配置导出或对应版本支持的配置备份方式保存一份。

### ② 区分配置文件和场景集合

配置文件主要保存输出、视频、音频和推流等参数；场景集合保存场景、来源及布局。只备份其中一项，可能无法完整恢复整个工作环境。

### ③ 升级前先做备份

升级 OBS 或插件前，先保存场景集合和配置文件，并记录关键插件版本。升级后先检查场景、来源、音频设备和录制输出，不要直接开始重要直播。

### ④ 定期检查录制目录

定期清理已经确认不再需要的临时录制文件，并确保重要素材至少有一份独立备份。不要把 OBS 缓存、原始素材和最终成片全部放在同一个没有备份的磁盘分区。

## 9. 常见问题排查

### ① OBS 录制出来是黑屏

先确认使用的是显示器采集、窗口采集还是游戏采集；检查来源是否被隐藏、是否被其他来源遮挡，以及目标程序是否选择正确。

Windows 笔记本可能存在核显和独显分工，OBS 与目标程序使用不同图形处理器时，某些采集方式可能异常。可以尝试切换采集方式，并检查 Windows 图形设置和显卡驱动。

### ② 只有画面没有声音

检查音频混音器是否有电平变化，再检查设备选择、系统权限、音轨勾选和输出设置。

如果使用多音轨，播放器可能默认播放 Track 1 以外的音轨。导入剪辑软件确认各轨道是否存在。

### ③ 麦克风有回声或重复声音

检查是否同时采集了麦克风的多个副本，或者是否同时启用了全局桌面音频与应用音频捕获。监听设备也可能造成回授，必要时关闭不需要的监听。

### ④ 录制画面卡顿或丢帧

打开 **查看 → 统计信息**，区分渲染延迟、编码延迟和网络丢帧。录制时优先检查前两项；推流时还要检查网络丢帧。

可逐项降低输出分辨率、帧率或编码负载，并关闭不必要的浏览器来源和滤镜。每次只改一类设置，方便判断原因。

### ⑤ MP4 文件无法播放或录制异常中断

如果录制过程中发生断电、系统崩溃或 OBS 异常退出，MP4 可能因为容器索引未完成而无法正常播放。后续录制可优先使用 MKV，再在完成后重新封装为 MP4。

### ⑥ 升级 OBS 后插件无法加载

先确认插件是否支持当前 OBS 版本和系统架构，再查看插件作者的更新说明。不要从其他版本目录随意复制 DLL 覆盖，也不要为了让旧插件工作而下载不明来源的旧版 OBS 安装包。

# 总结

OBS Studio 的学习路线可以分成三个阶段：

- **入门阶段**：能够创建场景、添加来源、录制屏幕，并确保画面和声音正常。
- **高级阶段**：能够配置编码器、分辨率、帧率、音频滤镜和多音轨，按用途完成高质量录制或稳定直播。
- **进阶阶段**：能够搭建完整场景工作流，使用回放缓存、虚拟摄像机、浏览器来源、投影、插件和自动化控制。

不要一开始就追求复杂插件和极限参数。先建立一套稳定的基础配置，完成几次短录制，再逐步扩展功能。对内容创作者来说，稳定、清晰、可重复的录制流程，比堆叠复杂效果更重要。
